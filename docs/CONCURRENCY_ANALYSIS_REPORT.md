# 동시성 문제 분석 보고서

## 1. 동시성 문제 발생 가능 지점

### 1.1 재고 관리 (Product Stock) - ✓ 제어 있음

- 위치: `ProductOptionRepositoryImpl.java:38-51`
- 현재 상태: ConcurrentHashMap + synchronized + PESSIMISTIC_WRITE 락 적용
- 문제점: 분산 환경에서는 작동하지 않음 (단일 서버에서만 유효)

### 1.2 주문 처리 (Order Creation) - ⚠️ 부분적 제어

- 위치: `CreateOrderUseCase.java:27-89`
- 현재 상태: 재고 차감 부분만 제어됨, UseCase에 @Transactional 없음
- 문제점: 주문 생성 중 예외 발생 시 재고만 차감되고 롤백 안 됨 (원자성 부족)

### 1.3 결제 처리 (Payment) - ✗ 제어 없음 (위험)

- 위치: `ProcessPaymentUseCase.java:16-35`
- 현재 상태: 동시성 제어 전혀 없음
- 문제점: 같은 주문에 대해 중복 결제 가능

### 1.4 쿠폰 발급 (Coupon Issuance) - ✓ 제어 있음

- 위치: `IssueCouponUseCase.java:16-36`, `CouponRepositoryImpl.java:56-68`
- 현재 상태: ConcurrentHashMap + synchronized + PESSIMISTIC_WRITE 락 적용
- 문제점: 중복 발급 체크와 재고 차감 사이 원자성 보장 안 됨, 분산 환경 미지원

### 1.5 포인트 관리 (Point/Balance) - ✗ 제어 부족 (위험)

- 위치: `ChargePointUseCase.java:18-40`
- 현재 상태: @Transactional만 적용
- 문제점: Lost Update 문제 (동시 충전 시 업데이트 손실로 금액 손실 가능)

## 3. DB를 활용한 동시성 제어 방안

### 3.1 Pessimistic Lock (비관적 락)

- **개념**: 트랜잭션 시작 시 공유 자원에 락을 걸어 다른 트랜잭션 접근 차단 (`SELECT ... FOR UPDATE`)
- **장점**: 데이터 정합성 확실히 보장, 구현 간단
- **단점**: 성능 저하, 데드락 가능성
- **적용 대상**: 포인트 충전/사용, 결제 처리

### 3.2 Optimistic Lock (낙관적 락)

- **개념**: 버전 번호를 통해 변경 감지, 커밋 시점에 충돌 검증
- **장점**: 성능 좋음, 읽기 작업 영향 없음, 데드락 없음
- **단점**: 충돌 시 재시도 로직 필요
- **적용 대상**: 주문 상태 변경, 쿠폰 사용 처리

### 3.3 Database Unique Constraint

- **개념**: DB 제약조건으로 중복 방지 (애플리케이션이 아닌 DB 레벨 보장)
- **장점**: 가장 확실한 중복 방지, 성능 영향 최소, 분산 환경에서도 작동
- **단점**: 스키마 변경 필요, 제약조건 위반 시 예외 처리 필요
- **적용 대상**: 주문별 결제 중복 방지, 사용자별 쿠폰 중복 발급 방지

### 3.4 분산 락 (Redis)

- **개념**: Redis를 활용한 분산 환경 락 (Redisson, Lettuce)
- **장점**: 분산 환경에서 완벽 작동, 세밀한 락 제어, 타임아웃 설정
- **단점**: 외부 의존성 추가, 구현 복잡도 증가
- **적용 대상**: 재고 관리, 쿠폰 재고 관리 (멀티 인스턴스 환경)

## 4. 권장 해결 방안

| 영역 | 우선순위 | 권장 방안 | 이유 |
|------|---------|----------|------|
| 포인트 관리 | 1순위 | Pessimistic Lock | 금액 손실 방지 필수 |
| 결제 처리 | 1순위 | Unique Constraint + @Transactional | 중복 결제 확실히 방지 |
| 주문 처리 | 2순위 | @Transactional 추가 | 원자성 보장 필수 |
| 쿠폰 발급 | 3순위 | Unique Constraint + Pessimistic Lock | 중복 발급 + 재고 원자성 |
| 재고 관리 | 3순위 | 현재 유지 or Redis (분산 시) | 현재 로직 유지 가능 |
